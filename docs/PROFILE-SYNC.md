# Versioned publication and safe local drafts — 2026-10-25

Incident evidence: production /profile/save and /profile/me /profile/load returned 409; UI said saved before server acceptance and mapped all 409 errors to a cross-device conflict. A corrected canonical birthdate could quarantine old encrypted profile data while the editor discarded the replacement revision. The previous SQL timestamp CAS also compared a PostgreSQL timestamp against a JS Date, losing sub-millisecond precision. The exact failed branch of any individual historical request is not recoverable from HTTP status alone.

The server now exposes an opaque SHA-256 revision for authenticated profile reads, including quarantined or missing profiles without exposing their old medical contents. A save requires that exact revision and atomically compares encrypted snapshot plus immutable identity. It never changes QR ID, never trusts client clocks, never relaxes identity checks. Public reads still fail closed and require requested-ID binding. No database migration, record deletion, billing/authenticator or encryption-key change.

The editor keeps owner-bound local drafts separate from confirmed server snapshots. Existing identity-matched local work can be reviewed and published over a quarantined old profile using a fresh revision. Only server-confirmed success creates QR artifacts or says published. Network errors, revision conflicts and refresh preserve drafts. Closing a tab stores a local draft instead of silently posting to the server. Same-account conflicting versions can be compared in a text-only table; the owner explicitly loads the published version or publishes the reviewed draft, still protected by CAS. Newer edits made during an in-flight save remain pending.

Upgrade: keep the current app session, refresh/reopen online without clearing website data or logging out, review the recovered draft and click Save and update my QR codes. If two devices hold different drafts, publish one, then compare the other before choosing. Do not fill the same medical history repeatedly or assume local-draft status means publication. A recreated account has a new QR ID; an old QR for a deleted account must be regenerated. There is no fallback to another cached patient when public verification fails.

Full editor/register/public-card DOM checks were also run with fictional data. Physical phone scan of the owner's corrected profile remains a user verification step; no live health profile was read or erased during this repair.
